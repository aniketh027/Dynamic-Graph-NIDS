ABSTRACT
Modern Network Intrusion Detection Systems (NIDS) increasingly utilise machine learning models to enhance threat detection by effectively analysing complex data patterns in network traffic. Graph-based techniques have been especially effective, utilising deep network relationships and detecting subtle irregularities that traditional signature-based methods often miss. These sophisticated models integrate both structural and temporal information, capturing network topology and entity relationships while enabling comprehensive analysis of attack progression patterns, allowing for early detection of sophisticated and evolving multi-stage intrusion campaigns.
Despite their significant analytical strengths, existing graph-based systems frequently require extensive manual configuration by domain experts and impose high computational costs, restricting their scalability and real-time usability in diverse operational contexts. These limitations particularly affect deployment in resource-constrained environments where computational efficiency is paramount for practical implementation.
This research addresses these fundamental constraints by implementing an innovative dynamic graph-pruning technique that uses attention scores to eliminate less important nodes and edges dynamically during inference, utilising the PyTorch Geometric framework for efficient graph operations. The attention-based mechanism continuously evaluates component relevance, automatically removing low-importance elements while preserving critical pathways that significantly contribute to threat detection decisions. Additionally, an automated feature extraction process is employed, using tools such as Scikit-learn to automatically derive meaningful correlations, temporal patterns, and behavioural anomalies from raw network data without manual intervention.
Extensive evaluations performed on widely recognised benchmark datasets, including CIC-IDS2018 and NF-UNSW-NB15-v2, validate the efficiency of these enhancements by demonstrating reduced memory consumption, lower processing latency, and improved detection accuracy across various attack categories. These optimisations collectively advance the adaptability and overall effectiveness of NIDS solutions, making them substantially more suitable for deployment in resource-constrained network environments.

1. INTRODUCTION
1.1 BACKGROUND
Network Intrusion Detection Systems (NIDS) have evolved from traditional signature-based approaches to sophisticated machine learning solutions capable of identifying complex attack patterns. The integration of Graph Neural Networks has marked a significant advancement, with recent research demonstrating the effectiveness of Heterogeneous Temporal Graphs (HTGraphs) in network flow analysis. These approaches represent network flows as HTGraphs with nodes corresponding to dynamically updated features and three types of edges: homogeneous (same feature type), heterogeneous (cross-feature correlations), and temporal (time-based dependencies).
Recent innovations have introduced Heterogeneous Temporal Graph Neural Networks with separate GATv2 layers for different edge types, and Adjustable Early Detection Decoders enabling flexible observation windows. Despite achieving superior performance, current graph-based NIDS face critical limitations: computational complexity that scales quadratically with graph size, extensive memory requirements that challenge deployment in resource-constrained environments, and manual feature engineering requirements that limit adaptability across diverse network environments.
The dynamic nature of modern cyber threats demands NIDS solutions that can adapt quickly to new attack patterns while operating efficiently within computational constraints. Traditional approaches often struggle with the heterogeneous nature of network features and the temporal dependencies inherent in network traffic, leading to suboptimal performance in real-world deployment scenarios.
1.2 MOTIVATIONS
Modern network environments, particularly IoT ecosystems and edge computing infrastructures, operate under significant resource constraints where traditional graph-based NIDS become impractical due to their computational overhead. The need for real-time intrusion detection with millisecond response times further exacerbates these challenges, as current approaches struggle to meet stringent latency requirements during graph construction and neural network inference phases.
The dynamic nature of network environments reveals another critical limitation: static graph structures fail to adapt to varying traffic patterns and computational availability. Current systems require extensive domain expertise for configuration, creating a significant bottleneck for widespread adoption. Network administrators often lack the specialized knowledge required to properly configure complex graph-based systems, limiting their practical deployment.
Scalability challenges become particularly acute as network infrastructures continue expanding, demanding NIDS solutions that demonstrate linear rather than quadratic complexity growth. Organizations require solutions that can scale with their growing network traffic without proportionally increasing computational costs or degrading performance.
Automated feature engineering represents a crucial gap in existing solutions. Current graph-based NIDS rely heavily on manual relationship definition, requiring significant expertise and limiting generalizability across different network environments. The absence of intelligent feature extraction and relationship discovery mechanisms prevents these systems from adapting to new attack patterns without extensive reconfiguration, creating maintenance overhead and reducing system effectiveness.
1.3 SCOPE OF THE PROJECT
This project addresses the computational and scalability limitations of existing graph-based NIDS through two primary innovations: Dynamic Graph Pruning and Automated Feature Extraction. These enhancements enable practical deployment in resource-constrained environments while maintaining sophisticated detection capabilities.
Dynamic Graph Pruning implements attention-based algorithms to identify and eliminate redundant nodes and edges during inference, reducing computational overhead while maintaining detection accuracy. This approach enables adaptive resource management, allowing systems to scale complexity based on available computational resources and performance requirements. The pruning mechanism operates intelligently, preserving critical relationships while eliminating redundant connections.
Automated Feature Extraction eliminates manual engineering requirements through intelligent algorithms that discover feature correlations, categorize features into appropriate types (time, packets, binary, bulk, window), and establish graph relationships automatically. This capability significantly enhances system adaptability and reduces deployment complexity across diverse network environments, enabling rapid deployment without requiring specialized expertise.
Evaluation and validation utilize benchmark datasets including CIC-IDS2018 and NF-UNSW-NB15-v2 to assess detection accuracy, memory consumption, inference latency, and scalability characteristics. The expected impact includes enabling deployment in IoT networks, edge computing infrastructures, and enterprise environments where computational resources are limited, while providing automated adaptation capabilities that reduce configuration complexity and enable rapid deployment across diverse network environments.
2. PROJECT DESCRIPTION AND GOALS
2.1 LITERATURE REVIEW
Wang et al. (2024) introduced K-GetNID, a novel early-and-transferable NIDS framework that represents each network flow as a Heterogeneous Temporal Graph (HTGraph). In this scheme, flow features of different types (e.g., time-series, packet-level, bulk, windowed) become distinct node types, with edges encoding both intra-type similarity and inter-feature correlations. The authors then designed a corresponding HTGNN (heterogeneous temporal GNN) that applies type-specific GATv2 attention layers for message passing. Crucially, K-GetNID incorporates an Adjustable Early Detection Decoder that yields predictions at multiple packet-count horizons, allowing the system to trade off accuracy for detection latency. Evaluated on CIC-IDS-2017 and UNSW-NB15, K-GetNID matched state-of-the-art deep models when full flows are available and outperformed baselines for partial flows, demonstrating significantly higher precision/recall under limited observation. The authors attributed this to their knowledge-guided graph design, which embeds domain structure (feature types and correlations) into the model. They also showed that this leads to better cross-domain transferability, since the graph construction reduces overfitting to any one dataset. The primary contribution was formalizing flow features as graph nodes guided by domain knowledge, rather than using host-topology graphs. However, Wang et al. did not address model efficiency at inference: their HTGraphs are static and relatively dense, and the decoder design does not consider resource constraints. They also did not explore how to prune or compress these graphs dynamically. For our project, K-GetNID’s HTGraph and multi-window decoder establish the baseline representation and early-detection mechanism. Its focus on inter-feature relations validates learning on structured graphs. The open challenge is extending this design to adaptive pruning: specifically, to maintain the decoder’s multi-horizon performance while sparsifying the HTGraph at runtime. Thus, K-GetNID motivates our work in that we will use its graph construction as a template and then investigate how to remove redundant nodes/edges without sacrificing early-detection accuracy (Wang et al., 2024).
Xiaoyan Hu et al. (2023) tackled the early intrusion-detection problem by embedding partial flow graphs. They modeled each bidirectional network flow as a compact graph of packets and applied a graph embedding pipeline (e.g. Graph2vec) to map this graph into a fixed-length vector. A lightweight classifier (such as a random forest or shallow MLP) then labels the flow. The key insight was that graph embeddings can capture packet-order and relational motifs that flat feature vectors miss. In experiments on CIC-IDS datasets, Hu et al. showed that even with only the first few packets of each flow, their graph-based method preserved discriminative structure: it achieved materially higher early-detection precision and recall and lower time-to-detection than tabular-feature baselines. This demonstrated that compact graph encodings recover relational cues lost by conventional feature extraction. The paper’s main contribution was confirming that transitioning from feature sequences to graph representations yields stronger signals for early detection, obviating the need for extensive manual feature engineering. However, the approach had limitations: it always built the full flow graph (or full partial-flow graph) and did not consider runtime graph optimization or pruning. The embeddings were computed in batch, without adaptation for resource constraints, and the method did not exploit attention or GNN layers for selective focus. For our project, Hu et al.’s findings directly support the use of HTGraphs: they validate that graph-based embeddings hold crucial timing and relational information. Their results motivate pruning strategies that preserve only the most informative substructures of these graphs, since those are the ones driving classification performance when flows are short. In particular, we will draw on their premise that graph form retains early-warning signals, and we will design methods to sparsify graphs (e.g. by removing edges or nodes) while keeping these motifs intact (Hu et al., 2023).
Duan et al. (2022) proposed a Dynamic Line-Graph Neural Network (DLGNN) to detect intrusions in streaming environments. They transformed the sequence of packets or communications into a line graph where each original edge (e.g. a packet transfer) becomes a node in the line graph. The DLGNN then operates on the evolving line graph, using temporal snapshots and aggregation to capture how interactions change over time. Importantly, Duan et al. integrated semi-supervised learning: they used label propagation and consistency regularization so that sparse attack instances (rare “edges”) are emphasized even without full supervision. On public NIDS benchmarks, this approach boosted recall on low-support attack classes compared to standard sequence models, at the cost of fewer parameters: by collapsing redundant temporal links into line-graph nodes, the representation compressed the data. The novelty of the work was twofold: first, representing flows via a line-graph elevates edge sequences to first-class status, which better encodes transition semantics; and second, updating the graph dynamically enabled online inference and continual training. For our objectives, DLGNN’s insights are highly relevant. It suggests that choosing an alternative graph transformation changes the information bottleneck in useful ways. In particular, it motivates designing edge-aware pruning heuristics for our HTGraphs: we may treat edges (or nodes corresponding to packet transitions) as units to either preserve or drop. Duan et al.’s use of semi-supervised signals also implies we should be careful not to prune away rare-attack cues. Thus, we plan to incorporate similar regularization ideas so that our pruning decisions favor keeping elements with high anomaly potential (Duan et al., 2023). Note that DLGNN focused on streaming detection rather than flexible early-detection horizons; bridging this to our adjustable decoder is an open area.
Pei et al. (2024) presented NIGNN, a graph neural network for NIDS that explicitly incorporates privacy-preserving mechanisms into its architecture. The core idea was to design the GNN message-passing so that node attributes are not directly exposed. They introduced a privacy-enhanced aggregation: each node adds noise proportional to its degree when contributing to neighbors, and the attention mechanism is masked or gated to restrict the context seen by any node. The result is a model with formal differential privacy guarantees: sensitive flow attributes (e.g. raw packet statistics) remain obfuscated even as information is shared across the graph. On standard flow datasets, NIGNN maintained accuracy close to non-private GNNs while significantly reducing information leakage. The primary contribution is showing that one can preserve structural learning capability in a GNN for NIDS without violating privacy constraints from legal policies. This is relevant to our project because it suggests that sparsification can aid privacy as well as efficiency. For instance, pruning low-attention neighbors (which NIGNN already biases) would further remove contexts where noise is added. The design choices in NIGNN - degree-sensitive masking and gated attention - are compatible with our goal: we can interpret pruning as a form of attention gating. A remaining challenge is to ensure that adaptive graph sparsification does not break these privacy guarantees or degrade detection of rare attacks. We will examine how pruning low-impact nodes intersects with differential privacy: ideally, pruning should reinforce privacy (by cutting potential leakage channels) while retaining the critical edges NIGNN would consider, per its privacy-accuracy trade-off (Pei et al., 2024).
Mao et al. (2025) introduced FeCoGraph, a framework that fuses federated learning and graph contrastive learning for few-shot intrusion detection. Each client converts its flows into line graphs and trains a local GNN with a label-aware contrastive objective: samples from the same class are pulled together in embedding space, while different-class embeddings are pushed apart. This improves class discriminability even with few labeled samples. Clients periodically share model updates (not raw data) with a central server, which aggregates them in a federated manner. FeCoGraph also uses a contrastive loss that explicitly leverages the sparse labels available. Experiments on cross-domain few-shot tasks showed that FeCoGraph outperformed both centralized and naive federated baselines by a significant margin: in one case it improved accuracy by ~8% over an e-graphSAGE baseline. The main contribution is demonstrating that combining label-guided graph contrastive pretraining with federated aggregation produces transferable, compact embeddings for few-shot NIDS. For our purposes, FeCoGraph’s success indicates that our automated feature extraction should target representations amenable to contrastive and federated learning. In other words, after pruning we should still be able to form embeddings that maintain inter-class margins. This suggests pruning must preserve the “positive pair” substructures that contrastive learning exploits. We will therefore test whether pruned HTGraph outputs remain well-separated in embedding space, following FeCoGraph’s paradigm (Mao et al., 2025). The use of line graphs in FeCoGraph also underscores that the specific graph form (flow vs. feature graph) can vary with similar principles.
Verkerken et al. (2023) proposed a pragmatic multi-stage hierarchical IDS to improve scalability and zero-day detection. Their system has a lightweight first stage that applies statistical tests, sketches, or simple binary classifiers to quickly filter out most benign flows. Flows deemed suspicious are escalated to one or more heavier stages with richer features and machine learning models. Crucially, they also included unsupervised novelty detectors at the front to catch unusual patterns that merit escalation. This tiered approach was validated on CIC-IDS datasets: it achieved high balanced accuracy (~96%) and correctly flagged most previously unseen attacks while cutting the amount of data processed by deep models by roughly 60–70%. The novelty of the work is its integrated escalation logic, which uses confidence thresholds to decide when to pass flows to deeper analysis. For our design, Verkerken et al.’s multi-stage blueprint is instructive: our dynamically pruned HTGNN would naturally fit as a mid-to-late stage, operating on flows already flagged as suspicious. In that role, we can prune aggressively to reduce the graph size (since we expect few flows to reach us), relying on the assumption that trivial cases have been filtered out. Verkerken et al. also suggest using strict handoff criteria; analogously, we will tie our pruning aggressiveness to upstream confidence scores. In summary, the multi-stage insight confirms that we need not apply the pruned GNN to all traffic, and guides how to coordinate our pruning with earlier screening (Verkerken et al., 2023).
Radoglou-Grammatikis et al. (2025) introduced AI4FIDS, a federated, multimodal IDS tailored to critical infrastructure. It jointly processes flows, host logs, and application-level telemetry while preserving data privacy via local model updates. The authors compared various federated aggregation strategies (FedAvg, robust aggregation, attention-based) under both non-IID distributions and adversarial label poisoning. They found that fusing multiple data modalities significantly outperformed single-modality models, and that robust aggregation schemes could mitigate some poisoned updates. The main contribution is evidence that cooperative federated learning with heterogeneous inputs dramatically improves detection of complex, multi-stage intrusions common in industrial settings, without centralizing raw data. This work is relevant for us because it highlights requirements for pruned graph representations in a federated pipeline: our HTGraph outputs should be compact, semantically consistent, and low-bandwidth so they can be aggregated across clients. It also underscores the importance of consistent normalization and modular feature design. For example, the need for robust aggregation suggests we should ensure our pruning does not introduce instabilities or amplify client bias. In practice, we will evaluate whether compact HTGraph features integrate smoothly with federated protocols (Radoglou-Grammatikis et al., 2025).
Yilun Hu et al. (2023) proposed PFTD, a privacy-preserving few-shot framework for APT detection via federated meta learning. In PFTD, each client collects a small support set of known attack flows and a query set of unlabeled flows. Each client fine-tunes a local model on its support set and evaluates on its query set, then sends gradients (not raw data) to a server. The server aggregates these meta-gradients to update a global model initialization. This meta-learning loop enables the model to quickly adapt to new attack variants with only a few examples, while never transmitting sensitive flows. PFTD also integrates lightweight differential privacy and client-specific personalization to prevent catastrophic forgetting of local patterns. Empirical results showed that with only a handful of labeled flows per attack, PFTD achieved high detection accuracy and adapted rapidly to held-out domains. The contribution is demonstrating that federated meta-learning can effectively detect rare, stealthy attacks (APTs) under privacy constraints. For our objectives, PFTD highlights that graph-based features should remain amenable to meta-learning: the pruned HTGraph embeddings we produce must still support fast adaptation and federated aggregation. We will test whether pruning degrades this few-shot adaptability. In particular, we may incorporate meta-learning in our pipeline so that pruned graphs can still be fine-tuned with minimal data, as suggested by PFTD’s design (Hu et al., 2023).
Bouzinis et al. (2025) introduced StatAvg, a lightweight preprocessing technique to reduce non-IID feature mismatch in federated NIDS. In StatAvg, each client computes local statistics (means, variances) of its training features and sends them to the server. The server aggregates these into global statistics, which it shares back with clients. Each client then normalizes its data using the global mean/variance before federated training. This simple extra step dramatically aligned feature distributions across clients. On heterogeneous IoT and enterprise intrusion datasets, StatAvg accelerated federated convergence and improved detection accuracy (notably reducing false positives) without extra raw-data sharing. The key insight is that sharing just statistical summaries eliminates much distribution drift. For our work, StatAvg underscores the importance of consistent input scaling in federated settings. We will adapt this idea by computing statistics on HTGraph node types (time series features, packet features, etc.) so that different sites normalize similarly even after pruning. One question is whether removing nodes/edges will disrupt these global stats; we will investigate if pruning can occur after StatAvg normalization or if the global stats need recalculation. In summary, StatAvg shows that harmonized inputs boost federated learning; we will incorporate a similar normalization step into our pruned-graph pipeline (Bouzinis et al., 2025).
Wu et al. (2025) proposed an anchor-graph clustering approach for IoT intrusion detection. They clustered similar flow and host behaviors into a set of anchor nodes, and then built sparse inter-anchor edges based on cluster proximity. This dramatically reduced graph density and memory requirements while retaining the structural patterns useful for classification. In experiments on IoT traffic, their anchor-based graphs were far more compact than explicit host-flow graphs, yet still enabled accurate intrusion detection. The main contribution was automating graph construction: instead of hand-crafted edge heuristics, clustering generated succinct graph motifs that preserved class-discriminative signals. This approach is well-suited to resource-constrained IoT/edge settings because of its low computational cost. However, Wu et al. sacrificed some temporal granularity in favor of spatial compactness and did not test early-detection with partial flows. They also did not examine how anchor summaries would interact with GNN attention mechanisms or federated learning: for example, the stability of anchors under non-IID client data was untested. For our work, the anchor-graph concept directly informs automated feature extraction and initial sparsification. Anchors could serve as supernodes or priors for pruning: we can start with anchor summaries and then use attention-driven pruning to refine which detailed nodes are needed. Our experiments will validate whether anchor compression preserves rare-attack cues under aggressive pruning, and whether anchor-based graphs remain effective when embeddings are synchronized across clients. These extensions will push anchor-graph ideas toward deployable, pruning-aware HTGraph pipelines (Wu et al., 2025).
Mohammadian et al. (2024) [13] proposed a pragmatic topology-driven leaf-prune reduction that removes peripheral nodes from static program and call graphs; they reported substantial runtime and memory benefits with only modest loss of central structural information, showing that very cheap topology-based heuristics can eliminate obvious redundancy before any learning step. Rabooki et al. (2025) [14] formalized graph distillation for provenance/APT graphs in GraphDART, applying condensation and core-set selection methods (random, herding, k-center) to extract compact representative subgraphs that preserve discriminative motifs; training on these distilled subgraphs produced sizable reductions in training cost while maintaining classification performance, demonstrating an optimization-driven second-stage compression complementary to simple heuristics. Wang et al. (2025) [25] contribute a different but complementary angle: they introduce a dual-channel high-order GNN (DHGNN) that separately encodes node attributes and high-order neighborhood structure, fusing the streams with channel attention to improve semi-supervised detection — a design that suggests attention and high-order aggregation can be used to prioritize informative substructures even when graphs are compressed. Taken together, these works point to two practical operating principles for pruning-aware HTGraph design: (1) inexpensive topology- and type-based coarsening (leaf/prune, component trimming) rapidly reduces graph density, and (2) learned or optimization-based condensation (distillation, core-set selection) produces compact, representative subgraphs for downstream learning. They also expose important gaps: few studies systematically evaluate early-detection latency, rare-class recall under aggressive pruning, or interactions with multi-horizon decoders. For our pruning-aware HTGraph + HTGNN pipeline these findings motivate a hybrid approach — fast structural coarsening followed by learned distillation or attention-guided refinement — paired with a strict evaluation regime that measures time-to-detection, per-class recall, and memory/latency tradeoffs, and includes anomaly-preserving regularizers so low-support attack cues are not inadvertently discarded.
Basak et al. (2025) [11] (X-GANet) combined GNN encoders with transformer-style embeddings, multi-scale anomaly scoring, cross-diffused attention, and adaptive masking to prioritize informative substructures; they showed that a coarse-to-fine attention cascade produces rapid, explainable anomaly scores and can selectively invoke heavier computation under tight latency constraints. Liu & Guo (2025) (DIGNN-A) [20] construct time-varying graphs and apply multi-head temporal attention to capture topology evolution in streaming traffic, demonstrating that temporal attention weights reliably track emergent anomalies and can serve as an online importance signal for retaining or evicting nodes and edges during inference. Li et al. (2023) [21] (EDGMAT) propose an edge-directed multi-head attention network that explicitly incorporates edge features and directionality into the attention computation; by jointly weighting node and edge attributes EDGMAT reduces manual feature engineering and identifies edges that are especially informative for classification, offering a concrete mechanism to use attention as an interpretable edge-importance signal in NIDS. Zhang et al. (2025) [23] (ResACAG) augment these ideas by adding residual connections and a global-broadcast mechanism alongside local attention to fuse long-range context and stabilize learning on larger graphs. Collectively, these works establish attention both as an interpretable importance indicator and as a natural pruning signal — attention scores can drive node/edge ranking, gate message passing, or trigger conditional activation of fine encoders in an anytime pipeline — while also warning of practical pitfalls (attention collapse on rare signals and sensitivity to non-stationarity). Robust designs should therefore include attention regularization (e.g., entropy or contrastive losses), temporal robustness measures, and evaluation under partial-flow observation windows to ensure attention-driven pruning preserves multi-horizon early-detection performance.
Bilot et al. (2025) (FEAE) framed malicious edges as few-shot categories and used self-supervised contrastive training to produce edge-centric embeddings that remained discriminative with minimal labeled examples, indicating that contrastive pretraining could make representations robust to subsequent node/edge removal [28]. Jianping Wu et al. (2024) developed a federated, attention-enabled GNN framework for network-attack detection and showed that locally computed attention-weighted summaries (fingerprint-weighted Jaccard or analogous measures) could be aggregated without sharing raw flows; their results implied that attention scores could double as compression criteria for transmitted summaries, thereby preserving privacy while reducing communication overhead [19]. Ngo et al. (2025) proposed a Top-K similarity graph construction and sampling-based GraphSAGE pipeline for IoT, linking nodes to their K most similar peers to produce sparse but informative graphs that reduced density while maintaining neighborhood signal and cross-domain transferability [18]. Together, these works suggested a practical federated pipeline for pruning-aware HTGraphs: construct compact local graphs (Top-K or anchor summaries), pretrain encoders with contrastive/few-shot objectives so embeddings tolerate pruning, and exchange only distilled summaries or attention-ranked updates to limit bandwidth. The cluster also raised empirical questions we must answer, how local pruning affects federated aggregation and personalization, whether contrastive pretraining preserves rare-attack separability on pruned subgraphs, and the precise communication-versus-accuracy trade-offs when only attention-ranked features are shared, experiments that are essential before deploying pruning strategies in distributed, heterogeneous environments.
2.2 GAPS IDENTIFIED
A major limitation of current graph-based Network Intrusion Detection Systems lies in computational scalability. The construction of heterogeneous temporal graphs requires substantial memory and processing resources, which grow quadratically with the number of nodes and the temporal depth of observation. This scalability bottleneck becomes particularly severe in real-time environments, where the system must process massive amounts of traffic continuously, making existing approaches impractical for deployment in large-scale or resource-constrained networks.
Another critical gap is the heavy dependence on manual feature engineering and domain expertise. Most existing implementations require experts in both cybersecurity and graph theory to carefully design features and graph structures. This reliance on handcrafted features introduces significant delays in system deployment and limits adaptability across different organizational contexts. Without automated mechanisms for feature discovery and relationship identification, current systems struggle to generalize effectively across diverse network infrastructures and attack landscapes.
The static nature of graph architectures used in existing models further limits their effectiveness. Current systems typically employ fixed graph topologies determined during preprocessing, which do not adapt to changes in computational resources or varying network traffic conditions during real-world operation. This rigidity leads to inefficient resource utilization, as redundant or minimally informative graph components are still processed, contributing to unnecessary computational overhead. Such static approaches fail to balance accuracy with efficiency in dynamic deployment scenarios.
Finally, graph-based NIDS models often demonstrate weak adaptation to evolving traffic patterns and novel attack vectors. While they may perform adequately on known datasets, their generalization capability deteriorates significantly when exposed to unseen attack types or zero-day exploits. This limitation arises from overfitting to static training distributions and insufficient mechanisms for handling distribution shifts in real-time traffic. As a result, these models exhibit reduced robustness in dynamic environments where new threats emerge continuously.
2.3 OBJECTIVES
The primary objective of this research is to design and implement intelligent graph optimization algorithms capable of dynamically identifying and pruning redundant components during inference. By integrating attention-based pruning mechanisms, the system will reduce computational overhead while preserving detection accuracy within acceptable thresholds. This adaptive optimization is particularly intended to enable efficient operation in resource-constrained or real-time deployment environments.
A second objective focuses on minimizing the reliance on manual feature engineering through the development of automated feature extraction and relationship discovery mechanisms. Machine learning–driven approaches will be employed to learn feature representations and establish meaningful graph connections, thereby reducing the requirement for domain expertise. Such automation will enable faster and more seamless deployment across diverse organizational contexts and network infrastructures.
Finally, the research aims to strengthen the model’s generalization capabilities in handling evolving traffic patterns and unseen attack vectors. By developing enhanced decoder architectures and training pipelines capable of addressing distribution shifts between training and operational data, the system will improve resilience against zero-day attacks. The ultimate goal is to ensure reliable detection accuracy across diverse environments while maintaining adaptability to emerging cybersecurity threats.
2.4 PROBLEM STATEMENT
Despite significant advances in graph-based Network Intrusion Detection Systems utilizing Heterogeneous Temporal Graphs that demonstrate superior detection capabilities in controlled research environments, current approaches face critical limitations preventing widespread deployment in resource-constrained operational environments. These limitations manifest as computational complexity scaling quadratically with graph size, creating prohibitive overhead for real-time deployment; extensive manual feature engineering requirements demanding specialized domain expertise and limiting system adaptability across diverse network topologies; static graph structures unable to dynamically adapt to varying computational resource availability during inference; and limited generalization capabilities to early detection scenarios characterized by input distribution shifts from reduced observation windows. 
These constraints severely restrict deployment opportunities in contemporary network environments, particularly Internet of Things ecosystems, edge computing infrastructures, and enterprise environments where computational resources are constrained and specialized cybersecurity expertise is unavailable. The fundamental research question addresses how intelligent graph optimization mechanisms and automated feature engineering techniques can be systematically integrated to enhance practical deployability of heterogeneous temporal graph-based Network Intrusion Detection Systems while maintaining sophisticated detection capabilities in resource-constrained operational environments.
2.5 PROJECT PLAN
The project implementation follows a systematic approach beginning with comprehensive analysis of existing heterogeneous temporal graph-based NIDS implementations and identification of computational bottlenecks through profiling and performance characterization. Development phases focus on creating dynamic graph pruning algorithms that intelligently eliminate redundant nodes and edges during inference while maintaining detection accuracy within specified thresholds.
Parallel development involves automated feature extraction systems that discover correlations and establish graph relationships through machine learning, incorporating intelligent categorization mechanisms that enable rapid deployment without specialized domain expertise. Core system integration combines enhanced HTGNN architectures with pruning mechanisms, optimized memory usage, and adaptive resource management capabilities.
Comprehensive evaluation utilizes benchmark datasets including CIC-IDS2018 and NF-UNSW-NB15-v2 to assess detection accuracy, computational overhead reduction, and transferability across different network environments. Final validation encompasses performance analysis under resource constraints, scalability testing with varying graph sizes and temporal sequences, and documentation of deployment scenarios, culminating in demonstration systems showcasing practical applicability in resource-constrained environments.

3.2 Functional Requirements
3.2.1: Data Ingestion
Description: The system shall ingest network traffic data in PCAP or NetFlow format. It shall extract individual flow records with features (timestamps, packet sizes, flags, etc.).
Inputs/Outputs: Input: PCAP file or stream; Output: normalized flow records (e.g. JSON or CSV).
Precondition: Raw network data is accessible.
Postcondition: Each network flow is represented as a time series of feature values.
Priority: High.
Acceptance Test: Given a sample PCAP containing 100 flows, the system correctly parses and outputs 100 flow records with expected fields.
3.2.2:  Feature Extraction and Categorization
Description: The system shall automatically extract relevant features from each flow and categorize them into types: Time, Packets, Binary, Bulk, and Window. For example, it shall record packet arrival times, sizes, protocol flags, and window counters over each flow.
Input/Output: Input: Raw or preprocessed flow record; Output: Structured features list or sequences.
Precondition: Valid flow record from 1.
Postcondition: Features are organized into sequences by type, ready for graph construction.
Priority: High.
Acceptance Test: For a flow with known packet series, the system outputs feature sequences matching the expected time, packet count, and flag patterns.
3.2.3: HTGraph Construction
Description: The system shall construct an HTGraph for each flow, with nodes representing the dynamic feature values (grouped by type) and edges as defined: homo-correlation (between same-type features), hetero-correlation (between different-type features sharing a base), and temporal (same feature across consecutive packets).
Input/Output: Input: Feature sequences from (2); Output: Graph data structure (nodes V, edges E_homo, E_heter, E_temp).
Precondition: Extracted feature sequences available.
Postcondition: A properly formed HTGraph (HTGraph_flow(T)) is created for each flow.
Priority: High.
Acceptance Test: For a flow with N=28 features over T=10 packets, the resulting graph has N×T nodes and edges; a sample graph matches the expected connectivity (e.g. temporal edges linking packet i to i+1).
3.2.4: Dynamic Graph Pruning
Description: The system shall apply an attention-based pruning algorithm during inference to remove less-informative nodes/edges from each HTGraph while preserving classification accuracy. Pruning decisions should be based on learned attention weights or significance thresholds.
Input/Output: Input: Full HTGraph of a flow; Output: Pruned HTGraph (with fewer nodes/edges).
Precondition: HTGraph built for a flow.
Postcondition: Reduced HTGraph retains key structures; original features not needed for classification are omitted.
Priority: High.
Acceptance Test: When pruning threshold is applied (e.g. remove nodes below a weight percentile), the pruned graph should have ≤50% of the original nodes yet the classifier’s detection accuracy drops by no more than 5% on a test set. (Measure before/after accuracy on a validation subset.)
3.2.5: HTGNN Model Training
Description: The system shall train the HTGNN model on labeled HTGraphs. The HTGNN uses three GATv2 modules (one for each edge type) to learn node embeddings, then fuses them to output a flow-level embedding. Training includes multi-query decoder loss.
Input/Output: Input: Training dataset of HTGraphs with labels; Output: Trained model parameters (checkpoint).
Precondition: Training data prepared (graphs labeled malicious/benign).
Postcondition: A model file is saved; training logs showing loss convergence are recorded.
Priority: High.
Acceptance Test: On held-out validation data, the trained model achieves ≥90% accuracy (or F1) on the multi-class classification task. Training loss decreases monotonically and final F1≥0.90 on CIC-IDS2018 validation set.
3.2.6: Inference and Classification
Description: The system shall apply the trained HTGNN (with pruning) to classify new flows as benign or malicious. The inference pipeline includes HTGraph creation, pruning, GNN forward-pass, and aggregation to a prediction.
Input/Output: Input: Single flow’s features or HTGraph; Output: Classification result (benign/malicious) and confidence score.
Precondition: Trained model loaded; flow ready as HTGraph.
Postcondition: Output label provided within latency constraints.
Priority: High.
Acceptance Test: Given a test flow from CIC-IDS2018, the system outputs a label and confidence; overall throughput meets ≥100 flows/sec (for small flows) and latency ≤100 ms. Accuracy over a test set matches expected F1.
3.2.7: Adjustable Early Detection
Description: The system shall implement the Adjustable Early Detection Decoder that produces multiple classification outputs for different packet-window sizes. Users can select an output corresponding to a desired response speed (e.g., 8-packet vs. full-flow).
Input/Output: Input: HTGraph and observation window sizes; Output: Array of N predictions (each for an increasing packet count window).
Precondition: HTGraph contains full feature sequence (all packets).
Postcondition: The system outputs N labeled predictions, with the earliest window’s result reflecting classification on partial data.
Priority: Medium.
Acceptance Test: On a flow with 16 packets, with N=2 queries (one sees first 8, one sees 16), the decoder returns two labels. The F1 of the early-window classifier (8 packets) is within 5% of the full-window classifier.
3.2.8: Class Balancing (SMOTE)
Description: The system shall apply SMOTE or similar oversampling during training to address class imbalance.
Input/Output: Input: Labeled training set (with imbalance); Output: Augmented balanced training set.
Precondition: Original training data is loaded.
Postcondition: Each minority attack class is oversampled so that its frequency approaches the majority class frequency.
Priority: Medium.
Acceptance Test: After SMOTE, each class has approximately equal representation (±10%). Training with and without SMOTE is compared: with SMOTE, recall on minority classes increases by ≥10%.
3.3 Non-functional Requirements
Performance: The system shall process input flows with an average end-to-end inference latency of ≤100 milliseconds per flow (measured on a test server). Training throughput should exceed 1,000 flows per second on GPU for large batches.
Memory Usage: Peak memory usage during training should be significantly lower than the full provisioned system memory (128 GB), owing to pruning and optimization. 
Scalability: The system shall scale roughly linearly: doubling data size or graph size should not more than double the processing time, thanks to pruning. It shall support batching of flows for throughput maximization.
Configurability: Thresholds for pruning aggressiveness and classification confidence shall be parameterized. The adjustable decoder’s number of queries (N) shall be configurable.
3.4 Data Requirements
Datasets: The system shall use established NIDS datasets: CIC-IDS2018 and UNSW-NB15. For example, CIC-IDS2018 provides flows with 80 raw features. All chosen data shall be labeled (benign vs. attack). The datasets may be pre-split into training/testing sets with stratified sampling
Data Preprocessing: Network flows must be extracted into feature sequences. Missing values in features should be handled by imputation (e.g. zero or mean). Class imbalance should be resolved by SMOTE oversampling.
Feature Types: Feature sequences will be grouped into the five node types: Time, Packets, Binary, Bulk, Window. Each feature time series becomes a node in the HTGraph.
Storage: All data files (raw, preprocessed, model files, logs) shall be stored on reliable storage. Approximately 50 GB is estimated for datasets.

4.3.4 Heterogeneous Temporal Graph Construction Module
Description: Transforms tabular network data into heterogeneous temporal graphs where nodes represent (feature, time) pairs and edges capture semantic relationships.
Components: Node construction with four-dimensional features: value, normalized time, category ID, and feature position. Three edge types: homo-correlation (same category), temporal (time sequence), and heter-correlation (cross-category relationships).
Purpose: To enable graph neural networks to capture complex interdependencies between network features that traditional methods cannot model effectively.
Input: A single data sample represented as a NumPy array of shape (temporal_steps, n_features). 
Output: A torch_geometric.data.Data object representing a single graph, containing x (node features) and edge_index (graph connectivity).
Pseudocode:
FUNCTION construct_htgraph(feature_sequence):
    //    Rule A: Homogeneous Edges
    FOR t IN each time_step:
        FOR category IN all_predefined_categories:
            nodes_in_group = FIND_NODES(time=t, category=category)
            ADD_ALL_PAIRS_EDGES(nodes_in_group) TO edges_list
    //    Rule B: Temporal Edges
    FOR feature IN all_features:
        nodes_for_feature = FIND_NODES(feature=feature)
        SORT nodes_for_feature BY time
        ADD_CONSECUTIVE_EDGES(nodes_for_feature) TO edges_list
    //    Rule C: Heterogeneous Edges
    FOR (feature1, feature2) IN all_predefined_correlations:
        FOR t IN each time_step:
            node1 = FIND_NODE(time=t, feature=feature1)
            node2 = FIND_NODE(time=t, feature=feature2)
            ADD_EDGE(node1, node2) TO edges_list
            ADD_EDGE(node2, node1) TO edges_list
    node_tensor = CONVERT_TO_TENSOR(nodes_list)
    edge_tensor = CONVERT_TO_TENSOR(edges_list)
    graph_object = CREATE_PYG_DATA(x=node_tensor, edge_index=edge_tensor)
    RETURN graph_object

FUNCTION forward(graph_data):
  x, edge_index = graph_data.x, graph_data.edge_index
  x = input_projection_layer(x)
  FOR i from 0 to num_layers:

    x_homo = homo_gnn_layers[i](x_input, edge_index)

  // Apply multi-query attention

4.3.7 Dynamic Pruning Module
Description: Applies scheduled, global unstructured L1 pruning to selected layers during training, masking the smallest-magnitude weights to reach a target sparsity while continuing optimization.
Components: 
Scheduler: computes epoch-dependent sparsity targets using linear, polynomial, or exponential schedules with start_epoch, end_epoch, and frequency.
Prunable set: collects parameters with a weight tensor across Linear and conv-named modules in the HTGNN stack.
Purpose: Applies scheduled, global unstructured L1 pruning to selected layers during training, masking the smallest-magnitude weights to reach a target sparsity while continuing optimization.
Pseudocode:
FUNCTION dynamic_prune_step(model, epoch, cfg, state):
    IF epoch < cfg.start_epoch OR (epoch % cfg.frequency != 0):
        RETURN NO_PRUNE
    progress = (epoch - cfg.start_epoch) / (cfg.end_epoch - cfg.start_epoch)
    IF cfg.schedule == 'linear':
        target = clamp(cfg.target_sparsity * progress, 0, cfg.target_sparsity)
    ELIF cfg.schedule == 'polynomial':
        target = clamp(cfg.target_sparsity * progress^3, 0, cfg.target_sparsity)
    ELIF cfg.schedule == 'exponential':
        target = clamp(cfg.target_sparsity * (1 - (1 - progress) ^2), 0, cfg.target_sparsity)
    ELSE:
        target = clamp(cfg.target_sparsity * progress, 0, cfg.target_sparsity)
    IF target <= state.current_sparsity + 1e-6:
        RETURN NO_PRUNE
    params_to_prune = []
    FOR module IN model.named_modules():
        IF hasattr(module, 'weight'):
            params_to_prune.APPEND((module, 'weight'))
    PRUNE.global_unstructured(
        params_to_prune,
        pruning_method=L1Unstructured,
        amount=target
    state.current_sparsity = compute_model_sparsity(model)  # zeros / total
    reinit_optimizer_and_scheduler_if_needed()
    RETURN PRUNED

HTGraph suitability | Contains explicit temporal features (flow duration, inter-arrival, active/idle times) that help build a heterogeneous temporal flow graph. | Uses static flow summaries (no intra-flow time series), so less inherent temporal detail; graph construction relies on matching IP/ports rather than dynamic series.
Labeling style | Multiclass labels (normal vs. each attack type) | Multiclass labels (normal + nine attack categories)
